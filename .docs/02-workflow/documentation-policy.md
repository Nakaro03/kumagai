# 設計記録の方針（Documentation Policy）

## テンプレート方針からの重要な逸脱

**一般的なAGENTS.mdテンプレートは「設計専用ディレクトリ・ファイルの作成を禁止し、PR description・docstring・design.md（50〜100行）の3箇所に限定する」ことを原則とする。本プロジェクトはこの原則を意図的に破る。**

理由: 本プロジェクトは数ヶ月にわたる研究プログラムであり、以下の情報はPR descriptionやdocstringには収まらない：

- 事前登録したGate 0/S/Lの基準と、実行後の判定結果
- 複数seed・複数ドメインにまたがる実験結果の時系列的な追記（1つのPRでは完結しない、数週間かけて仮説が更新される）
- 「なぜこの方向を捨てたか」という否定的結果の記録（後続の自分・エージェントが同じ失敗を繰り返さないために必須）

このため、`pnode_patent_runner/docs/*.md` に生きた設計文書を置くことを正式に許可する（例: `DUAL_FORCE_REDESIGN.md`, `EXIT_HAZARD_DESIGN.md`, `RESEARCH_PLAN_PREDICTABILITY.md`）。

## テストと実装が仕様書（共有インフラに適用）

**原則**: ドキュメントではなく、コードが真実

1. **テストが仕様書**: テストケース = 実行可能な仕様
2. **実装が設計書**: docstring = 設計判断、責務、制約
3. **PRが実装の文脈**: PR description = なぜこの実装にしたか

## 記録先（本プロジェクトでは6つ）

- **テスト**: 共有インフラの振る舞い（実行可能な仕様）
- **コードのdocstring**: 設計判断、責務、制約
- **PR description**: 実装の背景、他の案、トレードオフ
- **コミットメッセージ**: なぜこの実装にしたか
- **`pnode_patent_runner/docs/*.md`**: 研究プログラムの生きた設計文書（Gate判定、実験履歴、否定的結果を含む）——**テンプレート標準からの意図的な逸脱**
- **`outputs/**/*.json`**（小規模なもののみ、force-addで.gitignoreを越えて追跡）: 検証結果の生データ。`.gitignore`は学習済みチェックポイント・大容量データを除外するためのものであり、結果を裏付けるJSONは追跡対象とする

## 生きた設計文書のルール（`pnode_patent_runner/docs/*.md`固有）

- 1文書1研究方向を原則とする（Dual-Force、TAP-NODE、Exit Hazard等でファイルを分ける）
- 新しい実験結果は既存文書に**追記**する（§番号を増やしていく）。過去の記述を消さず、更新箇所には日付を明記する
- 結論が変わった場合は、古い結論を消さず「§X.Yで訂正」のように明示する（このプロジェクトの誠実性の規律——過去に何度か、初期の高い数値が後から手続き上の欠陥で撤回された実績があり、その過程自体を記録として残すことに価値がある）
- 文書の冒頭に必ず`Status`行を置き、現在の到達点（Gate通過/未通過/調査中）を一行で示す

## 原則

**上記6箇所以外に設計情報を記録しない。** 特に以下を禁止:

- ローカルのみの設計メモ（チーム・後続セッションに共有されない情報）
- `pnode_patent_runner/docs/*.md`以外の場所への新しい設計専用ディレクトリの追加

## 検索方法

```bash
# PRで設計判断を探す
gh pr list --search "exit hazard"

# コミットで探す
git log --grep="exit-hazard"

# コードで探す
rg "def diagnose_exit_hazard" --type py -A 20

# 研究の生きた設計文書を探す
ls pnode_patent_runner/docs/*.md
```
