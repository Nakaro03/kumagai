# セキュリティ（Security）

## データの機密性

- `data/processed/`配下は実在企業名・発明者名を含む特許データ。姉妹リポジトリ`kumagai-patent-analysis`は実クライアント（熊谷組）の競合分析にも使われるため、**このリポジトリの実データ・実企業を含む出力を、無関係な第三者サービスやパブリックな場に共有しない**
- 研究成果（AUC等の集計値）の公開は問題ないが、個別企業名を含む生データ・出力例の外部共有は避ける

## 認証情報の管理

- **環境変数**: `.env`で管理
- **.gitignore**: `.env`を除外
- 現状このリポジトリ自体は外部APIキーを直接扱わない（Codex/Context7等のMCPサーバー自体の認証は`claude mcp`側で管理）

## pickle等の安全でないデシリアライゼーション

- 姉妹リポジトリ（`kumagai-patent-analysis`）では、出所不明のpickleファイル読み込みが実際にRCEチェーンの一部になった実績がある。本リポジトリでも`.pt`（PyTorchチェックポイント）・pickle形式のファイルは、**このリポジトリ自身が生成したものだけ**を読み込む
- `torch.load()`で`weights_only=False`が必要な場合（学習済みモデル全体の復元等）、読み込み元が信頼できることを確認する

## セキュリティベストプラクティス

- **最小権限の原則**: MCPサーバーは必要最小限のsandbox/approval-policyで実行する（Codex MCPは`read-only`＋`never`をデフォルトとし、書き込みが必要な場合のみ明示的に変更する）
- **依存関係の更新**: 定期的にセキュリティパッチを適用
- **コードレビュー**: 認証情報の漏洩がないか、実企業データの不用意な共有がないか確認
